# Carbon launch kit

Everything here is meant to be copied, not to sit unread. Positioning and
proof points are drawn from the live product (the `apps/web` site and the
committed `benchmarks/results/latest.json`), so keep them in sync with the
real numbers.

## One-liner

> Carbon turns an OpenAPI/AsyncAPI/GraphQL/protobuf/HAR description into a
> **stateful** local replica — POSTs create records, GETs return them, and
> snapshots reset the world between test runs.

## Why now (the wedge)

Integration tests are the worst part of shipping an API product. You either
(a) hit a real third-party API and pay for every flaky red build, or (b) hand-
maintain mocks that return canned responses and drift from the real service.
Carbon's wedge: **a replica that models state and relationships instead of
responses**, so the same fixture behaves like the real system without the
network, the cost, or the shared staging environment.

## Positioning vs. the incumbents

| Tool              | What it does                   | Where Carbon differs                                   |
| ----------------- | ------------------------------ | ------------------------------------------------------ |
| MSW               | Intercepts fetch/XHR per test  | Real HTTP server; state survives across requests       |
| WireMock          | Stub mappings + scenarios      | No stub authoring — infer the graph from the spec      |
| Prism             | Validates + mocks from OpenAPI | Holds state and relationships, not just example bodies |
| Recording proxies | Replays captured traffic       | Replay is a _feature_ of Carbon, not the whole product |

## Proof points (from the committed benchmark suite)

- **6/6** stateful consistency checks pass (create → read → update → read →
  delete → read).
- **~43k req/s** HTTP throughput over loopback, 0 non-2xx.
- **~13 ms p95** snapshot restore for a 10k-row, 5-resource state.
- **~174 ms p50** cold start (CLI spawn → health endpoint).
- **~241 KB RSS per row** in the in-memory engine.

Numbers are regenerated by `pnpm bench` and gated in CI by
`benchmarks/scripts/gate.ts`.

## Launch post draft (Hacker News / Show HN)

**Show HN: Carbon — a stateful API replica you generate from your spec, not hand-write**

I spent too much of my career keeping mocks honest. `POST /users` creates a
user in the real API, but the mock returns a canned 201 and then `GET /users`
comes back empty — so the test passes while the integration is broken.

Carbon fixes that by compiling an API description (OpenAPI, AsyncAPI, GraphQL,
protobuf, HAR, Postman) into a **behavior graph** and serving it as a real
local HTTP server that mutates state the way the real service would:

```bash
carbon emulate --from ./openapi.yaml --port 8787
curl -X POST localhost:8787/pets -d '{"name":"Fido"}'
curl localhost:8787/pets          # → [{"name":"Fido","id":"pet_…"}]
```

It's not a fixture server. It infers resources and relationships, snapshots
and restores whole-state baselines in CI, and can even replay recorded
production traffic and detect drift.

No signup to try the playground: https://carbon-web-psi.vercel.app/try
Repo: https://github.com/TaxCollector23/carbon

Would love feedback on the state-inference model — it's the part I'm least
confident generalizes to messy real-world specs.

- [x] Homebrew: `brew install carbon-dev/carbon/carbon`

## Call to action ladder

1. **Hands-on:** open `/try` and make a pet, read it back, delete it.
2. **Local:** `npm i -g carbon-api && carbon try --sample petstore --open`.
3. **Team:** create a project in the dashboard, ingest your spec, share a snapshot.
4. **Pay:** Team seats unlock shared snapshots, drift detection, and Slack alerts.
